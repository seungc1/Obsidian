# 폐점·재계약 리스크 조기경보 모델 — 최종 보고서 (팀 공유용)

[[1. Projects/폐점 재계약 리스크 조기경보 모델]]의 최종 결과만 간추린 보고서(2026-07-28 전체 갱신 — 알고리즘 교체, 결합 판단, 조항 추천 기능까지 반영된 최신 상태). 비전공자도 읽을 수 있도록 전문용어(RMSE, SHAP 등)는 최대한 풀어서 설명했다. 실험 과정 전체가 궁금하면 [[3. Resources/폐점 리스크 모델 - 발표자료 (팀 공유용)]]과 코드 저장소의 `docs/design.md` 참고.

---

## 1. 이걸 왜 만들었나

프랜차이즈 본사는 자기 가맹점이 수백~수천 개인데, 어디가 위험한지 미리 알 방법이 마땅치 않다. 이 프로젝트는 "우리 가맹점 중 어디가 문 닫을 위험이 높은가"를 데이터로 미리 짚어주고, "그럼 어떤 조치를 취해야 하는가"까지 가이드로 연결하는 게 목표다.

**중요한 전제**: 이 모델은 "몇 % 확률로 폐업한다"는 정밀한 점괘가 아니다. **"여러 가맹점 중 상대적으로 어디가 더 위험한가"를 줄 세워주는 참고 지표**로 설계됐고, 그렇게만 써야 한다.

---

## 2. 두 개의 모델을 만든 이유

같은 문제를 두 가지 범위로 나눠서 풀었다.

| | **v1 (전국 모델)** | **v2 (서울 모델)** |
|---|---|---|
| 범위 | 전국 프랜차이즈 브랜드 | 서울 지역 매장만 |
| 비교 단위 | 브랜드 vs 브랜드 | **같은 브랜드 안에서** 매장 vs 매장 |
| 왜 필요한가 | 전국 어디서든 쓸 수 있음 | 매장 단위로 더 정밀하게 짚어줌 |

**왜 서울만 따로 만들었나**: "이 매장이 저 매장보다 위험하다"를 판단하려면 매장이 위치한 동네(상권)의 실제 폐업 통계가 있어야 하는데, 이런 상세 통계를 자동으로 가져올 수 있는 곳이 전국에서 **서울뿐**이었다. 다른 지역(경기·대전 등)도 비슷한 통계는 있지만 사람이 웹사이트에서 눈으로 보는 형태로만 제공돼서, 프로그램이 대량으로 자동 처리할 수 없었다. 그래서 "전국 어디서든 대략 판단"(v1)과 "서울은 매장 단위로 정밀 판단"(v2)으로 역할을 나눴다.

---

## 3. v1 — 전국 브랜드 모델, 최종 결과

**모델: 랜덤포레스트**(2026-07-28, 원래 쓰던 알고리즘에서 교체 — 근거는 5절 참고)

- **가장 위험한 신호는 "업종 동료 브랜드들의 최근 해지율"** — 같은 업종의 다른 브랜드들이 요즘 많이 문을 닫고 있다면, 우리 브랜드도 위험 신호로 본다. 다른 어떤 정보보다 압도적으로 강한 신호였다.
- 그다음으로는 **초기 투자비용 규모**(인테리어비·이행보증금 등), **업종 분류 자체**, **매장 주변 경쟁점포 수** 순으로 중요했다.
- 반대로 **가맹본부의 재무상태·법 위반 이력, 브랜드의 최근 성장세**는 거의 쓸모가 없는 것으로 확인됐다(데이터가 부족했던 탓이 큼).
- **성능**: 아무 정보 없이 평균값으로 찍는 것보다는 나은 수준까지 개선했지만, 절대적으로는 아직 약한 모델이다. 다만 "위험도 상위 10%" 매장과 "하위 10%" 매장을 비교하면 실제 해지율이 뚜렷한 차이가 나서, 극단적으로 위험한 곳/안전한 곳을 가려내는 용도로는 실용적이다.
- **주의할 업종**: 서비스 업종(수리·미용 등 서비스 성격 업종)은 이 모델이 순위를 거의 못 맞힌다 — 이 업종엔 참고 이상으로 쓰면 안 된다.

---

## 4. v2 — 서울 매장 모델, 최종 결과

**모델: LightGBM**(2026-07-28, 원래 쓰던 알고리즘에서 교체 — 근거는 5절 참고)

- **가장 위험한 신호는 "그 동네 상권이 최근 침체되고 있는지"** — 상권 추정매출, 상권 전체의 폐업 추세, 그 동네 유동인구, 주민들의 소비지출이 상위권을 차지했다.
- **지하철역까지의 거리**도 유의미한 신호로 확인됐다(역에서 멀수록 위험) — v1엔 안 맞아서 뺐지만 v2엔 그대로 채택.
- 반면 브랜드 자체 정보(가맹비용·계약조건 등)의 영향력은 상대적으로 작았다 — **서울에서는 "어떤 브랜드인가"보다 "어디에 있는가"가 더 중요하다**는 뜻이다.
- **성능**: 아무 정보 없이 찍는 것보다 뚜렷하게 나아졌고, 알고리즘 교체 이후 예측-실측 일치도가 이전보다 큰 폭으로 개선됐다(자세한 수치는 5절).
- **주의할 점**: 업종 분류가 서울시 통계 체계에 억지로 끼워 맞춰진 브랜드(예: 뷔페를 "한식"으로 근사)는 신뢰도가 떨어진다. 매장이 9곳뿐인 소규모 브랜드도 아직 확신할 수준은 아니다.

---

## 5. 알고리즘 교체 (2026-07-28) — 왜, 그리고 얼마나 좋아졌나

"다른 알고리즘은 더 잘 맞는지 확인해봐"는 요청으로 시작해서, 아래 3단계 검증을 거쳐 실제로 교체까지 했다.

1. **8개 알고리즘 동일 조건 비교**(원래 모델·LightGBM·XGBoost·CatBoost·랜덤포레스트·전통 그래디언트부스팅·ExtraTrees·선형회귀)
2. **알고리즘별 세부 하이퍼파라미터 랜덤서치**(각 20회) — 유력 후보 발견
3. **20개 시드 반복 재검증** — 단일 결과가 우연인지 확실히 확인

| | v1 | v2 |
|---|---|---|
| 교체 전 → 후 | 원래 알고리즘 → **랜덤포레스트** | 원래 알고리즘 → **LightGBM** |
| 20개 시드 중 승리 | 18/20 | **20/20** |
| 통계적 유의성 | p=0.0003 | p<0.0001 |
| 순위 정확도(20시드 평균) | 개선 | 큰 폭 개선 |

**흥미로운 발견**: 그동안 "현재 모델 성능"이라고 불러온 숫자가 사실 운 좋은 특정 시드 하나의 결과였다는 게 드러났다 — 20개 시드로 평균 내보니 원래 알고리즘의 실제 평균 실력은 우리가 알던 것보다 낮았다. 이번 교체 검증 방법론(여러 시드로 반복 확인) 자체가 "모델 성능을 하나의 숫자로만 판단하면 안 된다"는 걸 보여준 셈.

같은 지하철거리 피처도 v1(전국)엔 방해가 되고 v2(서울)엔 도움이 됐던 것처럼, 같은 알고리즘도 v1/v2에 다르게 맞을 수 있다는 게 재확인됐다(v1은 랜덤포레스트, v2는 LightGBM이 각각 이김).

## 6. 실무 활용 — 두 가지 새 기능

### 6-1. v1+v2 결합 판단

서울 매장은 v1(브랜드 전체 위험도)과 v2(그 매장의 입지 위험도)를 **둘 다** 계산해서 4분면으로 분류할 수 있다:

- **고위험**: 업종도 흔들리고 입지도 나쁨 → 최우선 개입
- **업종 구조적 위험**: 입지는 괜찮은데 업종 전체가 흔들림 → 업종 트렌드 모니터링
- **입지 위험**: 업종은 괜찮은데 이 매장 입지가 나쁨 → 상권/접근성 개선
- **안전**: 둘 다 양호

서울 외 지역은 v1만으로 판단(v2는 자동 생략). v1과 v2 코드는 서로 독립적이라, 이 결합 기능 없이도 각자 그대로 쓸 수 있다.

### 6-2. 재계약 조항 자동 추천

특정 브랜드/매장 하나를 넣으면, "왜 위험한지"(SHAP 기반 상위 위험요인)를 찾아 **예방조치 + 재계약 조항 후보**를 함께 제시한다.

**⚠️ 중요한 안전장치**: 위험요인이 실제로 "위험한 방향"에 있는지 자동으로 다시 확인한다. 예를 들어 "유동인구가 적어서 위험"이라는 항목인데 실제로는 유동인구가 상위 94%로 아주 많은 경우, 시스템이 `⚠️ 방향 확인 필요` 경고를 자동으로 붙인다 — 관계가 항상 "낮을수록/높을수록 위험"으로 단순하지 않을 수 있기 때문(실제 테스트에서 이런 경우가 발견됐다). 조항 문구는 계약서에 바로 넣는 게 아니라 **법무 검토용 초안 제안**이며, 최종 판단은 항상 사람이 한다.

## 7. 한계 — 솔직하게 밝혀둘 것들

- **정밀한 확률이 아니라 순위 참고용**이다. "이 매장은 폐업확률 73%" 같은 식으로 쓰면 안 된다.
- v1은 **브랜드 단위**로만 판단한다 — 같은 브랜드의 매장끼리는 구분을 못 한다. 매장 단위 구분은 v2(서울)에서만 가능하다.
- v2는 **서울 지역에만** 적용 가능하고, 업종 분류가 억지로 끼워 맞춰진 일부 브랜드는 신뢰도가 낮다.
- v1의 서비스 업종, v2의 소규모/근사매핑 브랜드는 **아직 믿고 쓸 수준이 아니다.**
- 두 모델 다 회사 내부 실제 재무·매출 데이터가 없어서 공공데이터로 대체 추정한 부분이 많다 — 본사가 실제 매출/재무 데이터를 제공하면 더 정확해질 여지가 있다.
- **조항 추천은 아직 실제 성과로 검증된 적 없는 휴리스틱**이다 — SHAP 기반으로 합리적으로 만들었지만, "이 조항을 실제로 넣었을 때 효과가 있었는지"는 검증되지 않았다.
- **v1+v2 결합 판단의 상위 25% 임계값은 통계적으로 검증된 기준이 아니라 편의상 잡은 값**이다.
