## 요약 (핵심 3줄)
1. 결측치는 유형별로 4가지 방식(마스킹 문자 치환·inf/NaN 공통 클렌징·모델용 행 제거·범주형 '미분류' 대체)으로 나누어 처리함
2. 별도의 원-핫/라벨 인코딩은 사용하지 않음 — SHAP 모델 투입 변수가 전부 연속형 수치이고, 범주형 변수는 모델이 아닌 groupby 집계 키로만 사용됨
3. 스케일링은 목적에 따라 이원화함 — 공간분석(H-Lock Index)은 Min-Max 표준화, 분류모델(RandomForest)은 트리 기반이라 스케일링 자체를 적용하지 않음

## 1. 결측치 처리

### 1-1. 원자료 로드 단계 — 비공개 마스킹 문자 처리
가계금융복지조사 등 원자료에는 소수 표본 보호를 위해 특정 값이 `*`, `**`, `***` 같은 마스킹 문자로 비공개 처리되어 있음. 이를 pandas 로드 시점에 결측(NaN)으로 인식하도록 지정함.

```python
# vdr_pipeline.py:198-199
NA_VALS = ['*','**','***','****','*****','******','*******',
           '********','*********','**********','.']
```

`master_table_design.py:210-211`에도 동일한 목록이 `na_values` 파라미터로 적용되어 있어 두 스크립트 간 일관성을 유지함.

### 1-2. 공통 방어 함수 — `clean_inf_nan()`
나눗셈 연산(비율·지수 산출)에서 발생하는 `inf`/`-inf`를 NaN으로 바꾼 뒤 지정값(기본값 0)으로 채우는 공통 클렌저. 파이프라인 전 단계에 방어적으로 반복 호출됨.

```python
# vdr_pipeline.py:205-211
def clean_inf_nan(df: pd.DataFrame, fill_val=0) -> pd.DataFrame:
    """inf/-inf → NaN → fill_val 순서로 클렌징."""
    num_cols = df.select_dtypes(include=[np.number]).columns
    df[num_cols] = (df[num_cols]
                    .replace([np.inf, -np.inf], np.nan)
                    .fillna(fill_val))
    return df
```

적용 사례: 부동산편중도(자산 대비 거주주택 비중), 유동성_정체지수(거주주택금액/처분가능소득) 등 분모가 0이 될 수 있는 파생변수 산출 직후 항상 호출됨.

### 1-3. 모델 학습 단계 — 결측 행 제거(대체 아님)
SHAP/RandomForest 모델에 투입하는 변수는 대체(imputation) 대신 **행 자체를 제거**하는 방식을 택함. 값을 임의로 채워 넣는 것이 분류 결과를 왜곡할 수 있다고 판단했기 때문임.

```python
# vdr_pipeline.py:1197-1199
df = panel[feature_cols + ['고령층유형']].copy()
df = clean_inf_nan(df)
df = df.dropna(subset=feature_cols)
```

### 1-4. 범주형 변수 결측 — '미분류' 값 부여
그룹핑 키로 쓰이는 범주형 변수는 결측을 별도 범주로 명시해, 결측 행이 집계에서 조용히 누락되지 않고 '미분류' 그룹으로 드러나도록 처리함.

```python
# vdr_pipeline.py:396-398
df_multi['수도권여부'] = df_multi['수도권여부'].fillna('미분류')
df_multi['주택종류통합코드'] = df_multi['주택종류통합코드'].fillna('미분류')
df_multi['부채유무'] = df_multi['부채유무'].fillna('미분류')
```

## 2. 인코딩

**결론: 원-핫 인코딩·라벨 인코딩 등 명시적 인코딩 단계는 존재하지 않음.**

이유는 두 가지로 나뉨.

1. **분류·SHAP 모델 투입 변수가 전부 연속형 수치**: 거주주택금액, 처분가능소득, 순자산, 부채, 경상소득, 가구원수, 가구주 만연령 등 — 모두 금액·개수·나이 단위의 수치형이므로 인코딩 대상 자체가 없음.

```python
# vdr_pipeline.py:1191-1194
feature_cols = [
    RE_COL, '부동산편중도', INC_COL, '순자산', '부채',
    '경상소득(보완)', '경직적_비용비중', '가구원수', '가구주_만연령',
]
```

2. **범주형 변수는 모델 입력이 아닌 집계 키로만 사용**: 수도권여부·주택종류통합코드·부채유무 등 범주형 변수는 `groupby()`의 그룹핑 기준으로만 쓰이고 모델 피처로는 들어가지 않음. 따라서 수치화(인코딩)할 필요 자체가 우회됨.

## 3. 스케일링(표준화)

목적에 따라 스케일링 여부와 방식이 다름.

### 3-1. 공간분석용 — Min-Max 표준화 (H-Lock Index)
서로 단위가 다른 지표(면적, 금액, 건수 등)를 하나의 척도로 비교하기 위해 서울 25개 자치구 내에서 Min-Max 표준화를 적용함.

```
점수 = (해당 구 값 - 서울 최솟값) / (서울 최댓값 - 서울 최솟값) × 100
```

- 적용 대상: 주거고착지수·소득취약지수·부채압박지수·소비위축지수 4개 세부지수
- **방향 반전 처리**: 소득·소비 지표는 "값이 낮을수록 취약"이라는 반대 방향이므로, 표준화 후 `100 - 점수`로 뒤집어 "높을수록 취약"이라는 방향을 4개 지수 전체에 통일시킴 (원본은 [[3. Resources/2026 국가데이터 활용대회 2차 PPT 대본]] 슬라이드17 참고)

`master_table_design.py:405-407`의 LTI(유동성 함정 지수) 산출에도 동일한 Min-Max 함수(`_mm`)가 쓰임:

```python
def _mm(s):
    mn, mx = s.min(), s.max()
    return (s - mn) / (mx - mn + eps)
```

### 3-2. 분류모델용 — 스케일링 미적용
SHAP 분석에 사용한 RandomForestClassifier는 트리 기반 모델이라 변수 간 스케일 차이(예: 거주주택금액 단위 만원 vs 가구원수 단위 명)에 영향받지 않음. 따라서 StandardScaler·MinMaxScaler 등 별도 스케일링을 적용하지 않고 원본 수치를 그대로 학습에 사용함.

```python
# vdr_pipeline.py:1211-1215
model = RandomForestClassifier(
    n_estimators=300, max_depth=6, class_weight='balanced',
    random_state=42, n_jobs=-1,
)
model.fit(X, y)
```

## 4. 추가 방어 처리 (VDR 규정 — 참고용)

전처리는 아니지만 같은 파이프라인 단계에서 함께 적용되는 데이터 보호 규정. 전처리 슬라이드에 함께 언급하면 데이터 취급의 엄격성을 어필하는 데 도움이 됨.

- **K-익명성(k=5)**: 집계 건수가 5 미만인 행은 전부 제거해 소수 표본 재식별 위험을 차단함 (`vdr_pipeline.py:217-222` `apply_k_anonymity()`)
- 클래스별 표본수가 5 미만이면 SHAP 분석 자체를 스킵하도록 이중 방어함 (`vdr_pipeline.py:1204-1207`)

### 6-1. 원본 레이아웃 구조 분석
- 좌측 2단: ①결측치 처리 박스(도넛차트+설명) → ②피처 인코딩 박스(불릿 3개)를 세로로 배치
- 우측 상단: 전문용어 3개(Data Leakage·Label Encoding·RobustScaler)를 전구 아이콘 카드로 별도 설명
- 우측 하단: ③피처 스케일링 박스(히스토그램 6개+수식)
- 공통점: 번호 배지(①②③)로 프로세스 순서를 명시하고, 처리 내용과 "왜 이 용어를 썼는지 모르는 심사위원을 위한 용어 정의"를 분리해서 배치함

### 6-2. 우리 데이터에 맞게 적용할 구성안
숫자만 다른 게 아니라 **실제로 적용한 기법 자체가 다르므로**, 원본의 기법(Forward Fill·Label Encoding·RobustScaler)을 그대로 베끼지 않고 우리가 실제로 한 처리로 항목을 대체함.

| 원본 슬라이드 요소                        | 우리 프로젝트로 대체할 내용                                                                                                                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ①결측치 처리 (도넛차트: train/test 80/20)  | ①결측치 처리 — 마스킹문자(`*`,`**`...) → NaN → `clean_inf_nan()`으로 inf/NaN을 0 대체, 모델 투입 변수는 dropna, 범주형은 '미분류' 부여 (도넛차트 대신 4가지 처리 유형을 아이콘+짧은 설명 카드로 배치)                                               |
| ②피처 인코딩 (Label Encoding 적용)       | ②피처 인코딩 — **인코딩 불필요**임을 명시. 이유: 모델 투입 변수 9개가 전부 연속형 수치이고, 범주형 변수는 인코딩 대상이 아닌 groupby 집계 키로만 사용됨 (안 한 이유를 적극적으로 설명하는 카드로 구성 — "왜 안 했는가"도 방법론적 판단임을 보여줌)                                      |
| ③피처 스케일링 (RobustScaler, 히스토그램+수식) | ③피처 스케일링 — 두 갈래로 이원화됨을 표로 명시: (a) H-Lock 공간분석용 Min-Max 표준화 `(X-min)/(max-min)×100`, 소득·소비 지표는 100-점수로 방향 반전 (b) RandomForest 분류모델은 트리 기반이라 스케일링 미적용. 히스토그램 대신 서울 25개구 지도나 Min-Max 수식 박스로 대체 |
| 우측 전구 아이콘 용어박스(Data Leakage 등)    | 우리 발표에서 심사위원이 낯설어할 용어를 같은 형식으로 배치: **MECE**(상호배타·전체포괄), **K-익명성**(집계건수 5 미만 제거로 재식별 방지), **SHAP**(모델이 어떤 변수를 근거로 판정했는지 기여도로 설명하는 기법)                                                        |

### 6-3. 실제 슬라이드 초안 (개조식, 명사형 종결)

**제목**: 데이터 전처리

**① 결측치 처리**
- 비공개 마스킹 문자(`*`,`**`,`***` 등) → 결측(NaN)으로 인식 처리함
- 파생변수 산출 시 발생하는 inf/-inf는 NaN 경유 후 0으로 대체함(`clean_inf_nan`)
- 모델 학습 변수는 대체 대신 결측 행 제거 방식을 채택함(임의 대체로 인한 왜곡 방지)
- 그룹핑용 범주형 변수의 결측은 '미분류'로 명시해 누락 없이 집계에 포함함

**② 피처 인코딩 — 별도 인코딩 미적용**
- 모델 투입 변수 9개 전부 연속형 수치(금액·비율·나이)로 구성되어 인코딩 대상 자체가 없음
- 범주형 변수(수도권여부·주택종류 등)는 모델 피처가 아닌 groupby 집계 기준으로만 사용함

**③ 피처 스케일링 — 목적별 이원화**
| 용도 | 방식 | 비고 |
|---|---|---|
| H-Lock 취약지수(공간분석) | Min-Max 표준화, 0~100점 | 소득·소비 지표는 100-점수로 방향 반전 |
| SHAP 분류모델(RandomForest) | 미적용 | 트리 기반 모델은 스케일 영향을 받지 않음 |

**용어 설명 카드(우측 배치)**
- MECE: 겹치지 않고 빠짐없이 분류하는 원칙, 4유형 분류에 적용함
- K-익명성: 집계 건수 5 미만인 행을 제거해 개인 재식별 위험을 차단하는 규정
- SHAP: 모델의 판정 근거를 변수별 기여도로 분해해 설명하는 기법

### 6-4. 적용 시 유의점
- 원본 슬라이드의 기법(Label Encoding, RobustScaler)을 그대로 가져다 쓰면 실제로 하지 않은 처리를 한 것처럼 보이는 왜곡이 발생하므로, **레이아웃 패턴(번호배지+용어박스 분리)만 차용하고 내용은 우리가 실제로 수행한 처리로 전부 교체함**
- "인코딩을 안 했다", "스케일링을 일부만 했다"는 사실을 숨기지 않고 오히려 "왜 안 했는지/왜 이원화했는지"를 설명하는 방향으로 구성하는 것이 방법론의 신뢰도를 높임
