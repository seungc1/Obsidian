# 폐점·재계약 리스크 모델 — 코드 파일 구성

[[1. Projects/폐점 재계약 리스크 조기경보 모델]]의 코드 저장소(`C:\Users\yooyj\projects\closure-risk-model`, 별도 git repo) 구조 정리. 실제 코드는 vault에 복사하지 않고 이 문서에서 경로/역할만 참조.

## 요약 (핵심 3줄)
1. 노트북(`01`~`06`)은 최초 설계 당시의 스켈레톤만 남아있고, 실제 수집→라벨링→피처→모델링→검증은 전부 `src/` 아래 스크립트로 실행됨(2026-07-23 기준)
2. `src/`는 노트북에서 재사용할 로직(API 클라이언트, 피처, 모델, 추론 파이프라인)을 담당
3. API 키는 `.env`(git 제외)에만 저장하고 `docs/api_keys.md`에 상태만 기록 — 실제 값은 vault에도 절대 적지 않음

## 데이터 확보 현황 (2026-07-22)

`data/raw/sbiz/`에 전국 17개 시도 상가업소 CSV(기준연월 `202603`, 약 274만 건) 다운로드 완료. **단, 이 파일은 개폐업 이력이 아니라 특정 시점 스냅샷**이라 폐업 추정에는 다른 시점 스냅샷과의 diff가 필요함 — 자세한 내용은 [[3. Resources/폐점 리스크 모델 - 공공데이터 소스 목록]] 및 `docs/design.md`의 "B 소스 방법론 수정" 참고. 과거 시점 스냅샷 추가 다운로드가 다음 선행 작업.

국세청 사업자현황 100대 생활업종 API(15061118) 동작 확인 완료. 시군구x업종 조합별 당월/전월/전년동월 가동사업자 수를 한 번에 제공해 별도 diff 없이 MoM/YoY 순증감 계산 가능 — A 소스로 확정. 신규사업자 현황 파일(국세통계연보 표 9-8-25~27, `data/raw/nts/`) 검사 결과 최신 연도 단면만 제공해 신규/폐업 분리 역산은 불가능함을 확인 — 순증감(당월-전월) 자체를 사업 중단 신호 프록시로 사용하도록 방법론 확정.

`data/raw/kosis/`에 행정구역(동읍면)별/5세별/연도별 인구수 CSV 직접 다운로드 완료(83,842행, EUC-KR 인코딩). 배후인구 피처는 이 파일로 충분 — 별도 API 호출 불필요. 대용량통계자료 API(`statisticsBigData.do`)는 별도 키/사용자 통계표 등록이 필요해 사용 불가 확인.

`data/raw/kosis/`에 추가로 확보(2026-07-22): **`101_DT_6BD1132_*.xls`(시군구별 산업대분류별 기업 수 활동/신생/소멸)** — 국가 공식 소멸률 통계, A 소스 대체/검증 후보(가장 중요). 개업 코호트별 생존율 3종(산업별/시도별/시도x산업별), 상권별 소규모 상가 임대동향 3종(공실률/임대가격지수/임대료, 상권명 기반이라 코드 매핑 필요). 파일 형식 주의: `DT_6BD1132.xls`는 실제로 Excel 2003 XML(SpreadsheetML) + EUC-KR이라 `pandas.read_excel`로 안 열림, 정규식/XML 파싱 필요.

`data/raw/ftc/`에 가맹정보공개서 관련 AI 학습데이터(SQL2NL 형식) **12종 전체** 확보 완료(2026-07-22). `1112`(가맹점 변동 현황: 신규개업/계약종료/계약해지/평균영업일수)이 새로운 C 소스 핵심 — `계약종료+계약해지`가 통합 타겟과 정확히 일치. `1111`(등록취소 현황, 브랜드 2,719개)은 원인 분류 보조, `1105`(지역x브랜드별 점포수/평균매출) 등 나머지는 보조 피처. `1107`(가맹점목록현황)은 COUNT만 노출돼 개별 점포 단위 활용 불가. `SQL.DATAS.CONDITION`/`QUERY_RESULT` 필드 기준 파싱 필요, `NL_ANSWER`는 사용 금지(수치 버그).

**Cell 라벨 테이블 v1 완성 (2026-07-22)**: `src/labels/cell_table.py`로 A(국세청 100대 생활업종)+C(FTC 업종중분류 개폐점률)+KOSIS(기업생멸행정통계 소멸률) 세 소스를 실제로 합쳐 첫 Cell 라벨 테이블 생성·실행 완료. Cell 정의를 (행정동x업종중분류x연도) → **(시군구x NTS 100대 생활업종x연월)**로 변경(실제 소스 granularity 한계 때문 — 자세한 이유는 `docs/design.md` 참고). 24,433개 셀 생성, `data/interim/cell_labels_202604.csv`로 저장. 과정에서 FTC API가 `type=json`을 줘도 항상 XML(EgovMap)을 반환한다는 버그, KOSIS 산업대분류 명칭에 공백/쉼표가 섞여 있어 크로스워크 매칭이 깨지는 문제를 발견·수정함.

**v1 서울 실측 검증 결과 (2026-07-22)**: `src/labels/validate_seoul.py`로 서울 점포-상권 API(실측 폐업율)와 v1 soft_label을 대조(서울 400개 셀). **상관관계 사실상 없음(스피어만 0.03)** — 원인 분해 결과 A(순증감) 신호는 노이즈뿐이고, C(FTC 업종 base rate)는 실측과 역방향(-0.67), KOSIS 지역조정계수만 방향이 맞음(0.09, 업종 내부로 보면 더 강함). 과정에서 "중구" 등 시군구명 중복(여러 시도에 동명 시군구 존재) 조인 버그도 발견·수정.

**v2 재설계 결과 (2026-07-22)**: A를 3개월 평균으로 노이즈 완화, C는 라벨에서 제외(보조 피처로만), KOSIS 지역조정계수 가중치를 서울 실측 데이터로 회귀 추정(임의값 아님)해서 재시도. **결과: R²=0.008, 상관관계 0.07~0.09로 v1과 마찬가지로 사실상 예측력 없음.** 최적 가중치로도 안 됐다는 건 가중치 문제가 아니라 시군구 단위 매크로 통계 자체가 개별 점포 폐업을 설명하기엔 너무 거칠다는 뜻 — 방향 전환 필요(자세한 내용과 대안 3가지는 `docs/design.md`의 "v2 재설계 결과").

**방향 전환: 브랜드 단위 실측 타겟 완성 (2026-07-22)**: Cell 단위 매크로 프록시 대신 FTC `1112`(가맹점 변동 현황)의 브랜드x연도 단위 실측(`discontinuation_rate = (계약종료+계약해지)/연초가맹점수`)을 타겟으로 직접 사용하는 방향으로 전환. `src/labels/brand_target.py`로 14,244개 브랜드x연도 행 파싱 완료(유효 비율 3,951건, 평균 0.154). 소형 브랜드에서 rate가 1을 넘는 이상치 소수(5건) 발견해 클립 처리. `data/interim/brand_labels.csv`로 저장. 자세한 내용: `docs/design.md`의 "방향 전환 (b) 실행".

**브랜드 피처 테이블 완성 (2026-07-22)**: 나머지 FTC 파일(1104 가맹비용, 1102 계약기간/업종/개시일, 1105 매출/점포수)에서 `src/labels/brand_features.py`로 브랜드x연도 피처 13,845행 추출. 비용/계약기간/업종분류는 커버리지 61~65%로 양호, 매출/점포수(1105)는 대부분 지역별 세분화 질의라 전국 집계만 쓰는 현재 방식으론 커버리지 낮음(1.3% 미만, 남은 과제). 파싱 중 JSON 제어문자·손상 레코드 문제를 `src/labels/_json_utils.py`(레코드 단위 복구 파싱)로 해결. 타겟과 합쳐 `data/interim/brand_modeling_dataset.csv` 생성 — 타겟+피처 모두 있는 행 2,734개로 베이스라인 모델 학습 가능한 규모.

## 코드를 다시 열어볼 때 시작점
- 전체 설계 다시 보기: `docs/design.md`(26개 절, 실험 로그 전체) · 최종 리포트: `docs/report.md`
