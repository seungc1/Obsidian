# 메뉴 생애주기 관리 모델 — 데이터 소스 점검 (2026-07-30)

[[1. Projects/메뉴 생애주기 관리 모델 개발]]에서 사용할 데이터 소스를 웹서치로 실사 확인. 1차 조사(기획서에 이름이 있던 6개)에 이어, 지역 수요 신호 공백을 메울 **추가 후보 5개**까지 2차 조사 완료. 이 문서는 **"실제 채택"과 "제외/보류"를 분리**해서 관리한다 — 이름만 있고 못 쓰는 소스를 계속 기획서에 남겨두면 나중에 헷갈리기 때문.

## 요약 (핵심 3줄)
1. **MVP 즉시 채택 확정 4개**(2026-07-31 KMA 제외로 7→6, KOSIS·서울추정매출 Phase 2 이연으로 6→4) — 개발 착수에 지장 없음. MVP는 지역 보정 없는 단일 전국 곡선(기능정의서 §4 설계원칙3)
2. **네이버 검색어트렌드는 지역 필터가 없다는 게 확정**. 대체 후보였던 KOSIS 서비스업동향조사(시도 단위)·서울 열린데이터광장 추정매출(상권 단위, 서울 한정)은 2026-07-31 **Phase 2로 이연**(§0-3 지역군집 분리 보류 결정과 논리 통일 — 지금 붙이면 과설계). 완전한 전국 시군구 단위 대체재는 여전히 없음 — 이 갭은 그대로 인정하고 넘어감(§4)
3. **제외/보류 6개** — KMA(2026-07-31, 실효성 부족으로 제외), BC카드(승인 대기 중이라 보류), 소상공인365 전국매출·Google Trends·aT FIS·서울 외 지자체 API(자동화 난이도 또는 실효성 부족으로 제외)

## 1. MVP 실제 채택 데이터 (즉시 활용 가능)

### 1-2. 특일정보(공휴일·절기) API
- **접근/비용**: Open API, 무료+키필요(1만 건/일)
- **단위/주기**: 공휴일·24절기·잡절 각각 별도 엔드포인트
- **역할**: 이벤트/절기 신호
- **URL**: https://www.data.go.kr/data/15012690/openapi.do

### 1-3. 네이버 검색어트렌드(데이터랩) API
- **접근/비용**: Open API, 무료+키필요(1,000회/일)
- **단위/주기**: 일단위 상대지수. **지역 필터 없음** — 전국 단일 지수로만 사용(§4 참고)
- **역할**: 메뉴 키워드별 관심도 프록시
- **URL**: https://developers.naver.com

### 1-4. KAMIS(농산물유통정보) Open API
- **접근/비용**: Open API, 무료+키필요(cert_key/cert_id)
- **단위/주기**: 일별 품목별 도소매가, 농산물·축산물·수산물
- **역할**: 원가 리스크 신호(BOM 연동 전제)
- **URL**: https://www.kamis.or.kr/customer/reference/openapi_list.do
- **비고**: 가공식품·반가공품 품목 포함 여부는 BOM 매핑 작업 시 별도 확인 필요

### 1-5. 농식품부 외식업 경영실태조사 / 농진청 소비트렌드 조사
- **접근/비용**: 파일다운로드, 완전무료
- **단위/주기**: 연 1회(최신 2025년 조사, 2026-05-04 발표), 농진청은 월간 자료 별도
- **역할**: 정성적 맥락 — 사람이 요약해 LLM 프롬프트 배경지식으로 투입(파이프라인 아님)
- **URL**: https://www.data.go.kr/data/3076484/fileData.do

## 1-b. Phase 2 이연 데이터 (지역 보정계수용, MVP 미사용)

2026-07-31: 지역군집 분리(§0-3)가 목표고객사 확정 전까지 보류인데 지역 보정계수만 먼저 연동하는 건 앞뒤가 안 맞다고 판단, 아래 2개를 Phase 2로 함께 이연. **소스 자체는 여전히 무료/즉시 발급 가능** — 나중에 지역군집 분리를 재검토할 때 그대로 다시 꺼내 쓰면 됨.

### 1-b-1. KOSIS 서비스업동향조사 — 음식점업 생산지수
- **접근/비용**: KOSIS OpenAPI, 무료(회원가입 후 활용신청, 승인 대기 짧아 사실상 즉시급)
- **단위/주기**: **시도 단위**(시군구 아님), 월별/분기별
- **역할(Phase 2)**: 네이버트렌드가 못 주는 지역 신호를 광역시도 수준에서 보강 — 시도별 외식업 전반 경기 흐름 참고용
- **URL**: https://kosis.kr/openapi · https://kosis.kr/statHtml/statHtml.do?orgId=210&tblId=DT_21002D003
- **한계**: 시군구 해상도 아니고 업종 전체 생산지수라 메뉴/브랜드 단위 신호는 아님 — 지역 매크로 배경지표로만 사용

### 1-b-2. 서울 열린데이터광장 — 상권분석서비스(추정매출-상권)
- **접근/비용**: 파일다운로드(ZIP), 완전무료, 승인절차 없음
- **단위/주기**: 상권×업종 단위, 분기별 갱신
- **역할(Phase 2)**: 서울 지역에 한해 상권 단위 실측에 가까운 매출 신호 — 폐점 리스크 모델 프로젝트에서 이미 활용 검증된 소스와 동일 계열([[3. Resources/폐점 리스크 모델 - 공공데이터 소스 목록]] §4 참고)
- **URL**: https://data.seoul.go.kr/dataList/OA-15572/S/1/datasetView.do
- **한계**: 서울 한정 — 목표고객사가 비수도권이면 그대로 죽는 데이터라 지역군집 분리 재검토 전까지는 붙이지 않음

## 4. 남은 갭 (해결 아님, 인지하고 넘어감)

- **시군구 단위의 전국 수요 프록시는 끝내 찾지 못했다.** 서울은 상권 단위까지 가능하지만 그 외 지역은 시도 단위(KOSIS)가 최선 — 다만 이 두 소스 자체가 2026-07-31 Phase 2로 이연됐으므로, MVP 단계에서는 지역 보정을 아예 하지 않는 것으로 이 갭을 흡수. 기능정의서 §4 설계원칙 3에 반영 완료.
- BC카드 승인 결과에 따라 §2의 "보류" 소스가 §1로 승격될 수 있음 — 승인 응답 오면 이 문서 갱신.

## 7. 필요성 재검토 (2026-07-31, 채택 소스 재점검)

"목록에 있다"와 "모델 아키텍처(기능정의서 §6)에 실제로 꽂히는 자리가 있다"는 다르다. 7개 채택 소스 + 신규 후보 3개를 §6 파이프라인 단계·§7 출력 항목과 대조해 재점검.

### 명확히 필요 (파이프라인에 실제 소비처 있음)
- **네이버 검색어트렌드**: §7 "출시 최적 타이밍 권고"의 근거로 명시, §4 임계값 엔진(이동평균/기울기)의 유일한 입력값 — 이거 없으면 상태판정 로직 자체가 안 돌아감
- **KAMIS**: §6 원가 트리거 엔진의 유일한 입력 — 필수
- **특일정보(공휴일·절기)**: 캘린더 데이터라 예보 시계와 무관하게 항상 유효 — 필수
- **BOM(더미) / 자사 판매 데이터(더미)**: §6 원가 엔진, §8 백테스트의 전제 데이터 — 필수

### 재검토 여지 있음 (연결은 돼 있지만 실효성 의문)
- **KMA 중기예보**: 제공 범위가 **향후 11일**뿐인데, 이 모델이 산출하는 건 출시~단종까지 **수개월짜리** 생애주기 곡선(§1). 그런데 정작 §7의 "출시 타이밍 권고"는 근거를 "검색량 인덱스"라고만 명시하고 날씨를 언급하지 않는다 — KMA가 실제로 소비되는 지점이 설계서 어디에도 구체적으로 안 적혀 있음. "계절 신호"는 이미 특일정보(24절기)가 커버하므로, KMA는 **출시 임박 시점(11일 이내) 미세 조정용 그 이상의 역할이 불분명**. 용도를 §6에 명시하거나, 안 되면 빼도 되는지 확인 필요.
- **KOSIS/서울 열린데이터광장(지역 보정)**: §0-3에서 지역군집 분리 자체를 "목표고객사 지역분포 확정 전까지 보류"로 못박아뒀는데, 지역 보정계수(§4 설계원칙3)는 그 보류 결정과 별개로 지금 살아있다. 목표고객사가 어디인지도 모르는 지금 시점에 "서울 상권 데이터"(서울 밖이면 통째로 죽는 데이터)까지 미리 연동하는 게 MVP에 꼭 필요한지 — 지역군집 분리를 보류한 논리(과설계 방지)가 여기도 똑같이 적용돼야 하는 것 아닌지 재검토 가치 있음. Phase 2로 같이 미뤄도 되는 항목일 수 있음.
- **농식품부/농진청 리포트**: 연 1회/월간이라 갱신이 느리고 사람이 요약해 프롬프트에 수작업 투입해야 함. §6 신규 후보의 배민 트렌드 리포트가 메뉴명 단위로 더 구체적이라 **역할이 겹침** — 둘 다 쓰기보다 배민 쪽으로 대체하거나 우선순위를 낮추는 게 나을 수 있음.

### 신규 후보 3개 — 현재 아키텍처(§6)에 꽂을 자리가 없음
SGIS(경쟁밀도)·공정위 가맹정보(브랜드 매출)·배민 리포트(정성 트렌드, 위 항목은 대체 후보) 모두 §6 다이어그램의 기존 4단계(태그매칭→LLM곡선→임계값엔진→원가엔진) 중 어디에도 지금 당장 입력으로 안 물려 있음. 특히 SGIS·공정위는 "있으면 나중에 쓸 수도" 수준이지 지금 DoD를 막고 있는 갭이 아님 — §0-3(지역군집 분리 보류)과 같은 이유로 **지금 붙이면 과설계**. 배민 리포트만 "농식품부 대체재"로 즉시 검토 가치 있고, 나머지 둘은 백로그로 남겨두는 걸 권장.

**결론**: 3개 모두 §1(즉시 채택)로 바로 승격하기엔 검증 부족. 특히 SGIS는 §4 갭("시군구 수요 프록시 없음")을 메우진 못해도 밀도 신호로서 기능정의서 §4에 새 축을 추가할 근거가 될 수 있어 우선순위 높게 재조사 권장.

## 5. Notion "필요 데이터 정의" 마스터 DB 대조 결과 (2026-07-30 추가)

Notion에 이미 이 플랫폼 전체의 데이터 소스를 관리하는 **"필요 데이터 정의 - 소상공인 플랫폼"** DB가 있고, `FUNC-003-07`(메뉴 생애주기 관리)에는 이미 9개 항목이 "사용 데이터" 관계로 연결돼 있었다: BC카드/특일정보/네이버트렌드/KMA/KAMIS/농식품부/농진청 + **자사 매장 판매 데이터 (Phase 1-더미 / Phase 2-혼합)**. 이 문서(§1~4)의 웹서치 결과와 대조한 차이점:

- **BOM 데이터는 이미 결정돼 있었다**: "메뉴별 표준 레시피(BOM)" 항목이 파트=더미데이터·유형=자체생성으로 정의돼 있음 — 실연동이 아니라 팀이 만드는 임시 레시피표로 시작하기로 이미 정해진 것. 다만 **FUNC-003-07과의 연결(연결기능)이 아직 안 돼 있음** — 기능정의서 §12의 "BOM 미해결" 항목은 신규 결정이 아니라 **누락된 링크 연결**로 정정.
- **백테스트용 데이터가 이미 준비돼 있다**: "자사 매장 판매 데이터 (Phase 1 - 더미)"가 "계절 패턴 인위 삽입(정답 시나리오 포함)"으로 이미 FUNC-003-07에 연결돼 있음 — 기능정의서 §8에서 제안한 백테스트 절차를 이 데이터로 바로 실행 가능. 새로 만들 필요 없음.
- **⚠️ 해상도 필드 불일치**: Notion 레코드에는 KMA 중기예보·네이버 검색어트렌드 둘 다 "해상도: 지역"으로 기록돼 있으나, 본 문서 §1의 웹서치 검증 결과와 다름 — KMA는 광역(시도) 단위 관측소 코드까지, 네이버트렌드는 지역 필터 자체가 API에 없음(§1-3 참고). **Notion 쪽 필드가 실제보다 낙관적으로 기록됨** — 수정 여부는 사용자 확인 후 반영 예정(다른 팀원도 보는 공유 워크스페이스라 임의 수정하지 않음).
