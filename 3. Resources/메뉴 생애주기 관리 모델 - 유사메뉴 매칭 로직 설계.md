# 메뉴 생애주기 관리 모델 — 유사메뉴 매칭 로직 설계 (v1)

[[3. Resources/메뉴 생애주기 관리 모델 - 기능 정의서 (v1)]] §6의 "규칙 기반 태그 매칭" 단계를 구체화. 신메뉴 콜드스타트 문제를 풀기 위해, 판매이력이 없는 신메뉴를 판매이력이 있는 기존 메뉴 중 가장 비슷한 것들과 매칭해 LLM에 넘길 후보군을 만드는 단계.

## 1. 태그 체계 (5개 차원)

ML 임베딩이나 별도 학습 없이 **가중 다속성 스코어링**으로 충분하다고 판단(YAGNI — 후보군 추리는 데 의미론적 유사도까지는 불필요, LLM이 최종 판단을 하므로 규칙 단계는 "그럴듯한 후보를 놓치지 않는 것"이 목표).

| 차원 | 값 예시 | 비고 |
| --- | --- | --- |
| 카테고리 | 대분류(한식/중식/일식/양식/디저트/음료) × 중분류(찌개·전골/면류/구이류/튀김류/밥류/샐러드/베이커리 등) | 공정위 가맹정보 업종중분류와 다른 층위 — 메뉴 단위 분류라 별도 체계 필요(§4 참고) |
| 조리법 | 튀김/구이/볶음/찜·탕/생식(회·샐러드)/베이킹/음료제조 | |
| 주재료 | 돼지고기/소고기/닭고기/해산물/채소/두부·콩류/면(밀가루)/쌀/유제품 (다중 태깅 허용) | KAMIS 품목코드와 연결되는 축 — 같은 주재료 태그면 원가 신호도 함께 참고 가능 |
| 가격대 | 브랜드 평균가 대비 구간(하위/중위/상위) — 절대금액이 아니라 **브랜드 내 상대 구간**으로 정의 | 절대가격 구간(5천원 미만 등)은 브랜드마다 가격 포지셔닝이 달라 비교 왜곡 — 상대구간이 더 안전 |
| 계절연관성 | 봄/여름/가을/겨울/사계절무관/특정절기(복날·크리스마스·설날 등) | 특일정보 API(§5)와 연결되는 축 |

## 2. 유사도 스코어링

```
score = 0.35·cat_match + 0.25·ingredient_match + 0.20·method_match
      + 0.15·season_match + 0.05·price_proximity
```

- **cat_match**: 대분류 일치 0.5 + 중분류까지 일치 시 1.0 (부분 일치 허용)
- **ingredient_match**: 주재료 태그 집합의 Jaccard 유사도(다중 태깅이라 자카드가 자연스러움)
- **method_match**: 조리법 일치 여부(1/0), 조리법도 다중 태깅 시 자카드
- **season_match**: 계절연관성 일치 여부(1/0), "사계절무관"은 모든 계절과 0.5로 부분 매칭 처리(사계절무관 메뉴가 후보군에서 완전히 배제되지 않도록)
- **price_proximity**: `1 - min(|가격구간 차이|/2, 1)` — 상대구간이 3단계(하/중/상)이므로 인접 구간까지는 부분 점수

**가중치 근거**: 카테고리·주재료가 생애주기 곡선의 모양(피크 타이밍, 계절 민감도)을 가장 강하게 좌우한다고 보고 가장 높은 비중을 줌. 가격대는 생애주기 곡선 모양과 상관이 약하다고 보고 최저 비중 — 다만 이건 검증된 값이 아니라 초기 추정치이므로, [[3. Resources/메뉴 생애주기 관리 모델 - 기능 정의서 (v1)]] §8 백테스트 단계에서 가중치별 성능을 비교해 조정할 여지를 남겨둔다(하드코딩 값이 아니라 설정값으로 관리 — ponytail 원칙상 지금 튜닝 로직까지 만들 필요는 없고, 상수를 코드 상단에 노출해두는 정도로 충분).

## 3. 후보군 선정 로직

1. 전체 메뉴 마스터에서 **판매이력이 8주 이상 축적된 메뉴만** 후보 풀로 사용 — Notion "자사 매장 판매 데이터 (Phase 2 - 혼합)" 항목이 이미 "8주 이상 실측 데이터 축적 매장은 실데이터"를 기준으로 삼고 있어 이 임계값을 그대로 재사용(새 기준 발명 안 함)
2. 신메뉴와의 score를 계산해 **내림차순 정렬**
3. score ≥ 0.5 인 후보 중 **상위 5~10개**를 LLM 입력으로 전달
4. score ≥ 0.5 인 후보가 3개 미만이면 **니치 메뉴 폴백**(기능정의서 §9): 중분류 조건을 풀고 대분류만으로 재검색

## 4. 데이터 요구사항 (신규 확인 필요)

이 로직을 돌리려면 "메뉴 마스터" 데이터가 있어야 하는데, 현재 Notion 기능정의서 어디에도 **메뉴 단위로 5개 태그를 입력/관리하는 화면**이 정의돼 있지 않다. 확인된 것: "메뉴별 일별/시간대별 판매량"(더미데이터, 판매이력)과 "메뉴별 표준 레시피(BOM)"(더미데이터, 재료 배합비)는 있지만 **카테고리/조리법/가격대/계절연관성 태그 자체를 담는 마스터 테이블은 없음**. BOM의 재료 목록에서 주재료 태그를 자동 유추할 여지는 있으나(예: BOM에 "돼지고기 200g"이 있으면 주재료=돼지고기로 유추), 카테고리·조리법·계절연관성은 별도 입력이 필요.

**제안**: 새 화면을 만들기보다(YAGNI), `FUNC-003-07`의 "신메뉴 정보 입력" 단계에 이 5개 태그 입력 필드를 포함시키고, 기존 메뉴는 BOM 데이터와 함께 일괄 등록할 때 같이 태깅한다 — 별도 "메뉴 마스터 관리" 기능을 새로 만들 필요 없이 이 기능 안에서 최소 입력으로 해결.

  "후보군": [
    {
      "메뉴명": "...", "유사도": 0.82,
      "판매이력요약": { "출시일": "...", "피크시점": "출시 후 6주", "총판매기간": "22주", "계절패턴": "여름 성수기" }
    }
  ]
}
