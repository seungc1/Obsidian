# 폐점 리스크 모델 — 시나리오 테스트 (코치 데모용)

[[1. Projects/폐점 재계약 리스크 조기경보 모델]] — 실제 브랜드(쿠우쿠우/피자스쿨 등) 대신 **가상 시나리오**로 모델이 핵심 위험요인에 어떻게 반응하는지 보여주기 위한 데모. 실제 신규 브랜드/점포 스코어링에 쓰는 `src/pipeline.py`(저장소)의 `score_store()`를 그대로 재사용했고, 시나리오별로 입력 피처만 바꿔가며 실행함. 새 로직 없음 — 기존 파이프라인이 살아있는 모델임을 보여주는 목적.

## 시나리오 4종 + 자동화 데모 1종

| 시나리오 | 핵심 조건 | raw_score | calibrated |
|---|---|---|---|
| A. 안정형(저위험 기대) | 업력 15년·업종피어해지율 0.05·경쟁밀도 250m 3/500m 8·초기비용 3,500만 | 0.1053 | 0.1105 |
| B. 신생+고비용(고위험 기대) | 업력 1년·업종피어해지율 0.35·초기비용 7,000만 | 0.1221 | 0.1313 |
| C. 경쟁 0(한산, U자형 좌측 극단) | 경쟁밀도 250m 0/500m 0, 나머지는 중립값 | 0.2484 | 0.2226 |
| D. 경쟁 과밀(U자형 우측 극단) | 경쟁밀도 250m 20/500m 35, 나머지는 중립값 | 0.2555 | 0.2226 |
| E. 주소만 입력(자동화) | "서울 강남구 테헤란로 152" + 치킨 업종만 지정 → 카카오 지오코딩+실시간 경쟁밀도 자동 계산(250m 7/500m 16) | 0.1423 | 0.1420 |

> **2026-08-04 업데이트**: `scenario_demo.py`의 `BASE` 업종이 "치킨"→**"한식"**으로 바뀌면서 위 표의 B/C/D 수치가 재산출됨(A는 자체적으로 `total_initial_cost`만 다르고 업종은 BASE 공유라 동일하게 영향받았으나 소수점 수준이라 표기 유지). E는 `scenario_demo.py`와 별개로 그때그때 실행하는 1회성 명령이라 "치킨" 그대로 유지.

## 읽는 법 — 모델의 실제 성능 수준에 맞춰 해석

- **A vs B**: 업력·비용·업종피어해지율을 극단적으로 바꿔도 점수 차이가 크지 않음(0.105→0.122) — [[3. Resources/폐점 리스크 모델 - 발표자료 (팀 공유용)]] 5절에 명시된 대로 이 모델은 순위는 분별하지만 절대 정확도는 약한 모델이라는 한계가 시나리오 테스트에서도 그대로 드러남
- **C vs D**: 경쟁밀도가 양쪽 극단(0개 / 20+개)일 때 모두 중립 시나리오보다 점수가 크게 오름(raw_score 0.25 안팎, A 대비 2배 이상) — [[3. Resources/폐점 리스크 모델 - 피자스쿨 케이스 스터디]]에서 발견한 "U자형" 패턴(너무 한산해도, 너무 붐벼도 위험)과 방향이 일치. "치킨"→"한식"으로 업종을 바꾼 뒤 상승폭이 더 뚜렷해짐(raw_score 0.17/0.18 → 0.25 안팎) — 원인은 검증하지 않은 가설이지만, 활동 요약 문서의 "47개 브랜드 전수 탐색" 절에서 한식이 데이터셋의 77%를 차지해 모델이 한식 업종의 패턴을 가장 잘 학습했다는 기록이 있어 그 영향일 가능성이 있음. 단, 피자스쿨은 사례 하나뿐이었고 이번 시나리오도 동일 조건 관찰이라 일반화 근거로 삼기엔 이르다는 점은 동일하게 유지
- **C·D의 calibrated 값이 완전히 동일(0.2226)**: raw_score가 0.2484/0.2555로 벌어졌는데도 calibrated는 똑같음 — 캘리브레이션 홀드아웃 표본이 946건뿐이라 Isotonic Regression 계단함수가 거칠다는 한계([[3. Resources/폐점 리스크 모델 - 발표자료 (팀 공유용)]] 9절)가 시나리오 테스트에서 더 뚜렷하게 관측됨(고위험 구간의 계단 폭이 raw_score 0.07 차이도 뭉갤 만큼 넓다는 뜻)
- **E**: "주소 하나만 주면 경쟁밀도까지 자동 계산"이 실제로 동작함을 라이브로 확인 — 사람이 직접 경쟁점포 수를 세서 넣어야 했던 초기 한계가 해소됐음을 보여주는 시연용 시나리오

## 코드 — 코치님 앞에서 직접 돌리는 법

시나리오 4종을 한 번에 표로 보여주는 스크립트를 저장소에 저장해둠(`scenario_demo.py`, `score_store()`만 재사용하는 얇은 래퍼, 신규 스코어링 로직 없음).

```powershell
cd C:\Users\yooyj\projects\closure-risk-model
python scenario_demo.py                                          # 시나리오 4종 표로 출력
python -m src.pipeline --input-json docs\pipeline_input_example.json   # 단일 시나리오, [note] 로그까지 상세 확인
```

가장 임팩트 있는 시연은 주소만 입력해 경쟁밀도 자동계산 과정을 라이브로 보여주는 것(시나리오 E 재현):

```powershell
python -c "from src.pipeline import score_store; import json; print(json.dumps(score_store({'year':2025,'induty_lclas_nm':'외식','induty_mclas_nm':'치킨','address':'서울특별시 강남구 테헤란로 152','total_initial_cost':46500,'brand_age_years':5,'induty_peer_avg_discontinuation_rate':0.15}), ensure_ascii=False, indent=2))"
```
→ 실행 시 `[note]` 로그로 "주소 → 좌표 변환(카카오 지오코딩) → 경쟁점포 수 계산(BallTree)" 과정이 그대로 콘솔에 출력됨. 인터넷 연결 필요(카카오 API 실제 호출) — 발표 전 사전 점검 권장.

`scenario_demo.py`의 `SCENARIOS` 딕셔너리 값을 그 자리에서 바꾸고 재실행하면 코드 수정 없이 즉석 what-if 질문에 답할 수 있음.
