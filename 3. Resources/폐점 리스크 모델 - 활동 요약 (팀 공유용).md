# 폐점·재계약 리스크 모델 — 활동 요약 (팀 공유용)

[[1. Projects/폐점 재계약 리스크 조기경보 모델]] 담당자가 2026-07-21~22 동안 진행한 **데이터 수집** 작업을 팀원이 빠르게 파악할 수 있도록 정리한 요약본. 세부 기술 내용은 하단 "더 자세히 보려면" 링크 참고.

## 배경

담당 워크스트림은 "폐점 재계약 리스크 조기경보 모델"의 데이터 수집·모델링. 특정 브랜드 데이터(POS, 본사 계약정보)를 구하기 어려워, **공공데이터만으로 브랜드에 의존하지 않는 일반화된 폐업+재계약실패 통합 리스크 스코어**를 만드는 것이 목표. 실측 라벨이 없어 여러 공공데이터를 조합한 프록시 라벨(soft label)로 학습해야 하고, 이번 이틀간의 작업은 그 프록시를 구성할 데이터 소스를 실제로 발급·검증하는 과정이었음.

## 타임라인

**2026-07-21 — 설계 착수 & 첫 번째 데이터 이슈**
- 프로젝트 설계 및 코드 저장소(`closure-risk-model`) 스캐폴딩
- 소상공인시장진흥공단(SBIZ) 상가업소 API 키 발급, 전국 17개 시도 CSV 다운로드(약 274만 건)
- 다운받은 데이터를 검사해보니 **개폐업 이력이 아니라 특정 시점 스냅샷**이라는 걸 발견 → 폐업 추정 방법을 "스냅샷 2개 이상 diff"로 재설계

**2026-07-22 — API 소스 대거 확장 + 방법론 두 차례 재설계**
- 국세청 API를 재설계 두 번: ①개별 사업자번호 조회용 API는 지역·업종 집계에 못 씀 → ②"100대 생활업종" API로 대체 → ③신규/폐업 분리 역산도 데이터 한계로 불가능함을 확인해 "순증감(당월-전월)" 자체를 프록시로 쓰기로 단순화
- 서울 열린데이터광장 API **9종** 확보(같은 키로 SERVICE만 바꿔 전부 호출) — 그중 "점포-상권" API가 **폐업율을 역산 없이 직접 제공**한다는 걸 발견해 서울 지역 검증 기준으로 채택
- KOSIS(통계청) 인구 데이터 확보 — API 부분 확인 + 필요한 CSV(행정구역별/5세별 인구, 83,842행) 직접 다운로드로 보완
- 카카오 로컬 API(좌표→행정동 매핑) 확보
- 공정거래위원회(FTC) C 소스 2건 확보: 브랜드별 실제 등록취소 이력(2,719개 브랜드) + 업종별 개폐점률 API

**2026-07-22 (계속) — C 소스 재정의 + KOSIS 국가 통계 발견 + Cell 라벨 테이블 v1 완성**
- FTC 페어데이터 학습자료를 3종에서 **12종 전체**로 확장 확보 — `1112`(가맹점 변동 현황: 신규개업/계약종료/계약해지)가 우리 통합 타겟(폐업 OR 재계약실패)과 정확히 일치해 C 소스의 새 핵심으로 교체
- FTC 업종별 개폐점률/개황 API 2종 추가 확보, 공정위 "가맹사업 현황 통계" 보도자료(PDF)로 검증 자료까지 확보
- KOSIS에서 **"기업생멸행정통계"**(국가 공식 소멸률 통계)를 발견 — 시군구x산업대분류x연도별 활동/신생/소멸 기업수를 직접 제공. 지금까지 우회 추정하던 걸 대체/검증할 수 있는 자료
- **A+C+KOSIS 세 소스를 실제로 합쳐 Cell 라벨 테이블 v1을 완성** — 전국 24,433개 셀(시군구×업종) 단위 위험 점수 산출까지 실행 완료

## 알아두면 좋을 핵심 결정 4가지

1. **B 소스(SBIZ)는 "폐업 이력"이 아니라 스냅샷** — 한 시점의 사진 한 장 같은 데이터라서, 폐업을 알려면 다른 시점 데이터와 비교(diff)해야 함. 과거 시점을 여러 경로로 찾아봤지만 구할 수 없어서, 지금은 SBIZ를 라벨 소스가 아니라 "위치·경쟁밀도 참고용 데이터"로 역할을 좁혔음.
2. **A 소스(국세청)는 정밀한 폐업 건수 대신 "순증감"으로 단순화** — 원래는 신규/폐업을 정확히 나누려 했지만 국세청 통계가 그 정도로 세밀하지 않아서, "이 지역·업종이 늘었는지 줄었는지"만 신호로 사용. 이후 KOSIS 기업생멸통계라는 국가 공식 소멸률 통계를 찾아서, 이걸로 A 소스를 검증/보완하게 됨.
3. **C 소스 핵심이 등록취소 데이터에서 "가맹점 변동 현황"으로 바뀜** — 처음엔 등록취소 사유/일자 데이터가 핵심인 줄 알았는데, FTC 학습자료 12개를 전부 뜯어보니 "가맹점 변동 현황"(신규개업/계약종료/계약해지 수)이 우리 타겟(폐업 OR 재계약실패) 정의와 정확히 일치하는 걸 발견.
4. **서울은 답이 있다** — 서울시가 상권x업종 단위로 실제 폐업율을 이미 계산해서 공개하고 있어서(`점포-상권` API), 전국 프록시가 얼마나 정확한지 서울 데이터로 검증할 수 있게 됨.

## Cell 라벨 테이블 v1이 어떻게 만들어졌나

- **단위 변경**: 원래 목표는 "행정동×업종중분류×연도"였는데, 실제 확보한 데이터들의 최소 공통 단위에 맞춰 **"시군구×국세청 100대 생활업종×연월"**로 조정함. 행정동까지 내려가려면 SBIZ 위치 데이터 + 카카오 좌표매핑 조인이 추가로 필요 — 다음 단계로 남겨둠.
- **업종 분류가 소스마다 다른 문제**: 국세청은 "100대 생활업종"(커피음료점, 미용실 등 소비생활 밀착형 100개), KOSIS는 훨씬 거친 "산업대분류"(도소매업 등), FTC는 프랜차이즈 전용 "업종중분류"(치킨, 한식 등). 셋을 잇는 공식 매핑표가 없어서 수작업으로 매핑표를 만들었고, 아직 100개 중 일부(주로 외식·서비스·도소매 관련)만 매핑함.
- **결과**: 전국 24,433개 셀 생성, 그중 약 5,360개 셀이 FTC 업종과, 약 9,657개 셀이 KOSIS 지역 데이터와 매칭됨. 나머지는 매핑이 안 된 업종이라 중립값으로 처리됨.

## 다음 단계 / 더 나은 모델을 위해 필요한 것

**라벨 검증 → v1도 v2도 실패, 근본적인 방향 전환 필요**
- 서울 실측 폐업율과 v1 soft_label을 대조한 결과 **상관관계가 사실상 없었음**(스피어만 0.03). 원인을 나눠서 보니: A(순증감) 신호는 노이즈뿐이고, C(FTC 업종 해지율)는 오히려 실측과 반대 방향으로 움직였고, KOSIS 지역조정계수만 방향이 맞았음(약하지만).
- 그래서 v2를 다시 만듦: A는 한 달이 아니라 3개월 평균으로 노이즈를 줄이고, C는 라벨 계산에서 아예 빼고, KOSIS 가중치는 감으로 정하지 않고 서울 실측 데이터로 회귀를 돌려서 "최적" 가중치를 구함. **그런데도 R²=0.008, 상관관계 0.07~0.09로 여전히 거의 예측력이 없었음.**
- 이건 중요한 신호다 — **최적 가중치로도 안 된다는 건, 문제가 가중치 배합이 아니라 "시군구 단위 월별/연별 매크로 통계로 개별 점포의 폐업 여부를 설명하려는 접근 자체"에 있다는 뜻**. 임대료·경쟁밀도·유동인구처럼 점포 바로 근처 단위 정보가 훨씬 중요할 가능성이 큼.
- 이것도 실패가 아니라 **검증이 제대로 작동한 것** — 이 방향을 계속 밀어붙였으면 처음부터 안 되는 모델에 시간을 더 썼을 것.

**방향 전환 완료 — 브랜드 단위 실측 타겟으로 교체**
- 지역 매크로 프록시를 포기하고, FTC의 "가맹점 변동 현황" 학습데이터에서 **브랜드×연도 단위 실제 계약종료/계약해지 수**를 뽑아 타겟으로 직접 쓰기로 했음. 이게 원래 프로젝트 목적(프랜차이즈 본사가 가맹점 관리 차원에서 폐업확률을 아는 것)과도 지역 프록시보다 훨씬 잘 맞음.
- 실제로 14,244개 브랜드×연도 데이터를 뽑아냈고, 그중 3,951개는 비율 계산까지 가능(평균 15.4%). 연초 가맹점이 1~2개뿐인 아주 작은 브랜드에서 비율이 100%를 넘는 경우가 소수 있어서 100%로 상한을 씌워뒀음.
- 남은 한계: 이건 여전히 브랜드 단위지 "개별 가맹점 하나하나"는 아님 — 개별 점포 데이터(가맹점목록현황)는 개수만 나오고 상세 정보가 없어서 여전히 못 구함. 그래서 지금까지 만든 지역 지표(A, KOSIS)는 라벨이 아니라 "이 브랜드가 어느 지역에 많이 퍼져있는지"를 알려주는 보조 피처로 다시 쓸 계획.

**브랜드 피처(설명변수)까지 완성**
- 타겟만 있으면 모델을 못 만드니, 나머지 FTC 파일에서 "왜 폐업/해지가 늘어나는지"를 설명할 피처도 뽑았음: 가맹비용(보증금·인테리어비·교육비 등), 계약기간(최초/갱신 몇 년인지), 업종분류, 브랜드 개시일, 매출 수준.
- 13,845개 브랜드×연도 피처 행이 나왔고, 타겟(변동현황)과 합치니 **둘 다 있는 행이 2,734개** — 이 정도면 베이스라인 모델을 바로 학습시켜볼 수 있는 규모.
- 파싱 과정에서 원본 JSON 파일 자체에 결함(문자열이 잘린 채 다음 레코드로 넘어가는 손상된 레코드 등)이 있는 걸 발견해서, 레코드 하나하나를 따로 복구해서 읽는 방식으로 우회함.
- 아쉬운 점: 매출/점포수 데이터는 대부분 "지역별로 쪼개서" 조회하는 형태라, 전국 합계만 쓰는 지금 방식으론 커버리지가 낮음(1.3% 미만) — 나중에 지역별 데이터까지 살리는 작업이 남아있음.

**Cell 세분화**
- 지금은 시군구 단위인데, SBIZ 위치 데이터(좌표) + 카카오 좌표→행정동 매핑을 조인하면 행정동 단위까지 내려갈 수 있음 — 원래 목표 단위에 더 가까워짐.
- 업종 매핑표도 지금은 일부만 채워져 있어서, 나머지 업종(가전제품수리점, 문구점 등)까지 확장하면 라벨 커버리지가 늘어남.

**피처 엔지니어링 (아직 시작 전)**
- 경쟁밀도: 카카오 좌표매핑 + SBIZ 위치 데이터로 반경 내 동일업종 점포 수 계산
- 유동인구·매출 트렌드: 서울은 API로 확보됨, 지방은 소스가 없어서 공백 — 대체 자료 필요할 수도 있음
- 임대료 부담: KOSIS 상권별 데이터가 있지만 "광화문", "명동" 같은 주요 상권명 기준이라 행정동과 연결하는 매핑 작업이 필요
- 브랜드 재무건전성/법위반 이력: FTC 학습자료 중 아직 안 쓴 파일들(가맹본부 재무현황, 법위반 현황)을 피처로 만드는 작업

**데이터 공백 (구조적 한계, 해결 방법 고민 필요)**
- 지방 지역의 유동인구/매출 데이터가 아예 없음(서울 열린데이터광장은 서울 한정) — 전국 일반화 모델의 약점으로 리포트에 명시 필요
- SBIZ 과거 시점 스냅샷은 여러 경로로 찾아봤지만 결국 못 구함 — B 소스는 라벨이 아니라 피처로만 활용하는 걸로 방향 정리됨

**모델링 단계 — 베이스라인 학습 완료, 예측력 거의 없음 (2026-07-23)**
- 브랜드×연도 실측 타겟+피처(2,734행)로 2024년 학습/2025년 검증(시간 기반 홀드아웃)으로 첫 모델 학습 완료
- **환경 이슈**: 원래 LightGBM으로 학습하려 했으나, 이 컴퓨터의 보안 정책(애플리케이션 제어 정책)이 LightGBM 내부 파일 로딩 자체를 차단해서 실행이 안 됐음 — 우회하지 않고, 같은 역할을 하는 다른 라이브러리(scikit-learn)로 대체해서 학습을 완료함
- **결과: 평균값으로 찍는 것보다 거의 나아지지 않음**(오차 0.239 vs 0.237), 예측 순위와 실제 순위의 상관관계도 사실상 0(0.037) — 지금 가진 피처(가맹비용·계약기간·업종분류)만으로는 브랜드가 폐업/해지할지 거의 설명이 안 됨
- 그나마 영향이 있던 피처: 갱신계약 기간, 업종중분류, 인테리어 관련 비용 순 — 그래도 전체적으로 미미함
- **해석**: Cell 라벨 실패가 "라벨(정답) 자체가 틀렸다"는 문제였다면, 이번은 "설명할 재료(피처)가 부족하다"는 문제로 보임. 초기 투자비용·계약기간 같은 한 번 정해지면 안 바뀌는 정적 정보는, 브랜드가 최근 잘 되고 있는지·경쟁이 심해졌는지 같은 "지금 상황"을 전혀 담지 못함
- 다음 우선순위: 브랜드별 시계열 피처(작년 대비 개폐점률 추세, 브랜드 규모가 커지는지 줄어드는지, 업종 평균 대비 이 브랜드가 유리한지) 추가

**시계열 피처 추가 후 재학습 (2026-07-23) — 개선 미미, 뜻밖의 발견**
- 4가지 시계열 피처를 새로 만들어 추가함: 작년 해지율, 작년 대비 가맹점 수 증감률, 작년 신규개업수, **같은 업종·같은 해에 다른 브랜드들은 평균적으로 얼마나 해지되는지(피어 평균)**
- 결과: 순위 상관은 조금 나아졌지만(0.037→0.084) 여전히 약하고, 오차는 오히려 살짝 나빠짐(평균값 예측보다도 안 좋음)
- **뜻밖의 발견**: 모델이 실제로 쓴 건 "브랜드 본인의 과거 이력"이 아니라 **"같은 업종에서 다른 브랜드들이 지금 얼마나 해지되고 있는가"** 하나뿐이었음 — 이 피처가 2위 피처보다 3배 가까이 중요했고, 정작 가설을 세웠던 브랜드 개별 이력(작년 해지율/규모증감/신규개업) 3개는 모델이 전혀 쓰지 않음(데이터가 있는 브랜드가 15~40%뿐이라 너무 듬성듬성해서로 추정)
- 즉, "이 브랜드가 잘하고 있는지"보다 "이 브랜드가 속한 업종이 요즘 힘든 시기인지"가 그나마 더 쓸만한 신호라는 뜻 — 다만 이거 하나에 모델이 너무 의존하면서 다른 부분에서 오차가 커진 것으로 보임
- decile/calibration 검증, 업종별·지역별 subgroup 안정성 확인은 피처 보강 이후로 보류

**"지금 문제를 풀려면 뭐가 필요한지" 검토 → 우선순위 1·2번 실행, 개선 원인이 밝혀짐 (2026-07-23)**
- 다음에 뭘 해야 할지 5단계로 우선순위를 매겼음: ①타겟 자체가 원래 예측 불가능한 노이즈인지 진단(공수 거의 없음) ②이미 확보한 데이터 재처리(1105 매출, 1111 취소사유, 저커버리지 피처 보완) ③모델의 피어평균 과의존 완화 ④신규 데이터 확보(가맹본부 매핑, 경쟁밀도) ⑤시간이 필요한 항목(표본 축적)
- **①번 진단**: 브랜드의 74%가 가맹점 10개 미만이라 "3개 중 1개 폐점=33%"처럼 해지율 자체가 원래 들쭉날쭉할 수밖에 없는 구조. 큰 브랜드에 더 무게를 주는 가중학습 + 큰 브랜드만 따로 떼서 평가해보니 순위 상관이 꾸준히 좋아짐(0.084→0.097→0.122→0.158) — **노이즈가 진짜 문제의 일부였음을 확인**. 다만 오차(RMSE)는 그래도 평균값 찍기를 못 이겨서, 노이즈 하나만으로는 다 설명이 안 됨.
- **②번 재처리**: (a) 매출 데이터(1105) 파싱 로직에서 실제 버그를 발견함 — 특정 지역(예: 강원) 값을 실수로 "전국값"인 것처럼 잘못 가져오고 있었음, 고쳤지만 애초에 이 데이터 자체가 극히 일부 브랜드에만 존재해서 여전히 거의 못 씀. (b) 등록취소 사유 데이터(1111)를 "작년에 취소 이력이 있었는지" 피처로 새로 추가(전체 브랜드 커버). (c) 저조했던 브랜드별 이력 피처 3종의 빈칸을 업종 평균으로 채워서 커버리지를 15~40%에서 거의 100%까지 끌어올림.
- **재학습 결과**: 오차가 평균값 예측과 거의 비슷해질 정도로 근접했고(1.6% 차), 순위 상관은 **0.156**까지 올라감(처음 0.037에서 4배 이상). **그런데 원인을 뜯어보니(SHAP) 이 개선은 전부 ①번(가중학습) 덕분**이고, ②번에서 새로 만들거나 빈칸을 채운 피처들은 하나도 안 쓰였음(커버리지를 100%까지 채웠는데도 기여도 0).
- **가장 중요한 결론**: "브랜드 개별 최근 이력(작년 해지율/성장/신규개업/취소이력)이 데이터가 부족해서 안 쓰인다"는 지난번 추측이 틀렸다는 게 확인됨 — 데이터를 다 채워줘도 안 쓰이니, 애초에 이 브랜드x연도 단위에서는 "작년에 어땠는지"와 "내년에 해지될지" 사이에 실질적인 관계가 없다는 뜻. 지금까지 확인된 유효 신호는 딱 두 가지뿐: 같은 업종의 다른 브랜드들 상황(피어 평균), 그리고 브랜드의 정적 속성(초기비용 구조·업종·업력).

**3순위: "피어 평균에 너무 의존한다"는 우려를 검증해보니, 오히려 우려가 틀렸음이 확인됨 (2026-07-23)**
- 모델이 "같은 업종 다른 브랜드들 상황(피어 평균)" 하나에 지나치게 의존하는 게 걱정돼서, 모델을 더 단순하게/조심스럽게 만드는 여러 설정을 시도해봤음(정규화)
- 결과: 설정을 이리저리 바꿔도 이 피처에 대한 의존도는 거의 안 줄어들었고, 오히려 **이 피처를 아예 빼봤더니 예측 순위 정확도가 반토막**남(0.156→0.105)
- 즉, "이 피처에 너무 의존한다"는 게 문제가 아니라 **지금 가진 피처들 중 이 피처가 거의 유일하게 진짜 쓸만한 신호**라는 뜻이었음 — 걱정의 방향이 틀렸다는 걸 확인한 셈
- 손해 없이 살짝 더 나아지는 설정 하나는 찾아서 기본값으로 반영함(순위 정확도 0.156→0.161)
- **모델을 이리저리 만지는 접근은 여기서 개선 여지가 거의 다 소진된 것으로 보임** — 다음 개선은 새로운 데이터(가맹본부 재무/법위반 연결, 경쟁밀도)를 확보하는 쪽이거나, 지금 수준에서 "위험요인→예방조치/재계약 조항" 가이드 표와 리포트 작성으로 넘어가는 쪽

**모델링 여정 마무리 — 최종 리포트 + 위험요인 가이드 표 (2026-07-23)**
- 모델을 더 손보는 접근은 여기서 멈추고, 지금까지 결과를 정리하는 리포트를 작성함(`docs/report.md`, 코드 저장소)
- **최종 성능**: 오차(RMSE)는 평균값 찍기보다 살짝 나쁘고(1.2% 차), 순위 정확도(Spearman)는 0.037→0.161까지 개선됐지만 여전히 약함 — "정확한 확률"이 아니라 "방향성 참고자료"로만 써야 한다는 점을 리포트에 명시함
- **위험요인 → 예방조치/재계약 조항 가이드 표** (프로젝트의 핵심 목적, 5개 카테고리):

| 위험요인 | 근거 강도 | 예방조치 예시 | 재계약 조항 예시 |
|---|---|---|---|
| 업종 구조적 위험(같은 업종 다른 브랜드들도 해지 중) | 강함 | 업종 트렌드 모니터링, 업종 전환 상담 | 업종 변경 시 계약 승계 조항, 매출기준 재검토 주기 단축 |
| 초기 투자·비용 부담(인테리어/보증금/이행보증금 등) | 중간 | 초기비용 회수 시뮬레이션 제공, 비용 재협상 지원 | 비용 회수 미달 시 유예/분할 조항 |
| 업종 분류(외식/도소매/서비스 특성) | 중간 | 업종별 표준 리스크 관리 템플릿 | 업종별 표준 재계약 템플릿 |
| 브랜드 업력(신생일수록) | 약함 | 개업 초기 밀착 지원(컨설팅·마케팅) | 성장 단계별 갱신조건 차등화 |
| 계약기간 구조 | 매우 약함(참고용) | — | 갱신주기를 실제 리스크와 연동 검토 |

- **못 다룬 부분**: 애초 계획했던 상권 쇠퇴/경쟁밀도/매출·유동인구/임대료 부담은 데이터를 브랜드 단위로 연결하지 못해 이번 리포트에는 못 넣었음 — 향후 과제로 명시
- **가장 큰 미해결 한계**: 이 모델은 여전히 "브랜드 단위"지 "개별 가맹점 하나하나" 단위가 아님. 원래 목표(개별 점포 폐업확률)를 완전히 달성하려면 점포 위치 데이터(sbiz+카카오)와 가맹본부 재무/법위반 데이터(매핑 필요)를 추가로 연결해야 함
- 자세한 SHAP 순위 전체·모델링 여정 요약표: `docs/report.md`(코드 저장소)

**4순위: 가맹본부 재무·법위반 데이터 연결 시도 → 매핑은 성공, 신호는 없음 (2026-07-23)**
- 가맹본부(회사)의 재무현황(순이익·자산·부채 등)이나 법위반 이력을 브랜드에 연결해보려고 했는데, 이 데이터셋에는 **"이 브랜드가 어느 회사 소속인지" 알려주는 정식 연결키가 아예 없음**을 확인(공정위 학습자료 전체 88만여 건을 다 뒤져봤지만 브랜드명과 회사명이 동시에 나오는 경우가 0건)
- 대안으로 "회사명이 브랜드명과 똑같은 경우"(1인 브랜드 회사 — 소형 프랜차이즈에 흔함)만 연결하는 방법을 씀 — 브랜드 3,443개 중 재무는 351개(10%), 법위반은 2개(0.06%)만 연결됨
- 연결된 데이터로 재학습해봤지만 **오차·순위 정확도가 소수점까지 완전히 똑같이 나옴** — 모델이 새로 넣은 재무/법위반 피처를 전혀 안 썼다는 뜻. 실제로 타겟과 매칭되는 비율이 2~3%밖에 안 될 정도로 너무 희소했던 게 원인으로 보임
- **정리**: "본부가 재정적으로 어려우면 가맹점도 위험하다"는 가설 자체가 틀렸다는 뜻은 아니고, 지금 연결 방법(정확히 같은 이름만 매칭, 여러 브랜드를 가진 회사는 전부 놓침)의 한계 때문일 가능성이 큼 — 이걸 더 밀려면 연결 방법 자체를 개선해야 함
- 여기서도 모델 쪽 개선 여지는 소진 — 지금 수준(Spearman 0.161)에서 리포트/가이드 표로 마무리하는 방향이 유지됨

**경쟁밀도 피처: 처음으로 "평균값 찍기"를 이김, 대신 순위 정확도는 나빠짐 (2026-07-23)**
- 1순위(경쟁밀도)를 다시 시작함 — sbiz 상가업소 데이터에는 브랜드명이 따로 없어서, 가게 이름 문자열 안에 브랜드명이 들어있는지 찾는 방식(문자열 매칭 알고리즘)으로 274만 개 점포 중 우리 브랜드 3,443개 중 **85%(2,807개)를 매칭**하는 데 성공함
- 매칭된 점포 하나하나에 대해 "반경 250m/500m 안에 같은 업종 점포가 몇 개 있는지"를 계산해서 브랜드 단위 평균을 냄 — 이 피처들의 데이터 커버리지가 **83%**로, 지금까지 추가한 어떤 신규 피처보다 훨씬 높음
- **결과**: 오차(RMSE)가 **이 프로젝트 전체에서 처음으로 평균값 찍기보다 좋아짐**(1.8% 개선) — 그런데 순위 정확도(Spearman)는 오히려 0.161→0.132로 나빠짐. 좋아진 지표와 나빠진 지표가 갈린 첫 사례
- SHAP에서 "매칭된 점포 수" 피처가 2위로 올라옴(업종 피어평균 다음) — 다만 이게 "경쟁이 치열하다"는 뜻인지 "이 브랜드가 전국적으로 매장이 많다(규모가 크다)"는 뜻인지는 더 확인이 필요함
- 이 프로젝트 목적(위험 "순위" 파악)에는 순위 정확도가 더 중요한 지표라서, 오차 개선을 그대로 받아들이기보다 트레이드오프로 리포트에 명시하기로 함

**"매칭된 점포 수"를 확인해보니 진짜 경쟁밀도가 아니었음 → 빼니까 오히려 다 좋아짐 (2026-07-23)**
- 위에서 의문으로 남겼던 "매칭된 점포 수"를 검증: 실제 경쟁밀도 지표와는 상관관계가 거의 0이었고, 브랜드의 전체 매장 수와는 강한 상관을 보임 — 즉 "경쟁이 치열한가"가 아니라 "이 브랜드가 얼마나 큰가"를 다른 방식으로 재발견한 것이었음
- 이 피처를 빼고(진짜 경쟁밀도 250m/500m만 남기고) 다시 학습해보니 **오차·순위정확도·평균오차 세 지표가 전부 개선**됨 — 오차는 여전히 평균값 찍기보다 좋고(1.3% 개선), 순위 정확도는 **이 프로젝트 전체에서 가장 좋은 값(0.165)**을 기록. 걱정했던 트레이드오프가 사라짐
- 이게 지금까지 나온 최종·최고 성능 — 최종 모델 피처셋으로 확정함

**모델링 워크스트림 완주 — 남은 3개 작업 마무리 (2026-07-23)**
- **업종별로 나눠 다시 확인**: 브랜드를 업종별로 쪼개서 봤더니, "서비스" 업종에서는 이 모델의 순위 분별력이 거의 사라짐(거의 무작위 수준). 종합 점수만 보면 이 편차가 안 보이는데, 실제로는 업종에 따라 모델을 믿을 수 있는 정도가 다름 — 서비스 업종 브랜드에는 이 모델의 위험도를 참고 이상으로 쓰면 안 됨
- 반면 예측 위험도로 브랜드를 10개 그룹으로 나눠보면, 가장 위험하다고 예측한 상위 10%는 실제로도 가장 낮은 하위 10%보다 해지율이 **2.75배** 높음 — 정밀하게 순위를 못 맞춰도 "위험군/안전군을 크게 나누는" 용도로는 쓸만하다는 뜻
- **캘리브레이션(점수를 실제 확률에 가깝게 보정)**: 표본이 적어서 계속 미뤄왔는데, 검증용 데이터를 반으로 나눠서 한쪽으로 보정 규칙을 만들고 다른 쪽으로 확인하는 최소한의 방법을 써봄 — 보정 전에는 "위험이 낮다고 예측한 건 실제보다 더 낮게, 높다고 예측한 건 실제보다 더 높게" 나오는 편향이 있었는데, 보정 후엔 이게 많이 줄어듦
- **실제로 점수를 뽑아보는 파이프라인**: 새 브랜드의 비용·계약조건·업종 등 정보를 넣으면 위험 점수가 나오는 스크립트를 완성함 — 이제 "분석"만이 아니라 실제로 입력값을 넣어서 결과를 받아볼 수 있음
- 이걸로 계획했던 모델링 작업이 전부 끝남 — 프로젝트 상태를 완료로 전환함
