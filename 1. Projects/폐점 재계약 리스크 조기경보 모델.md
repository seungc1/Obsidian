## 핵심 설계 요약
- 타겟: 폐업/철수 OR 재계약 실패를 하나의 "사업 중단" 리스크 스코어로 통합
- 라벨(2026-07-22 방향 전환): Cell(지역) 단위 매크로 프록시(A/B/C 가중합)는 서울 실측 검증 결과 예측력이 없음을 확인(v1/v2 모두 R²<0.01) → **FTC 가맹점 변동 현황(브랜드x연도 실측: 계약종료+계약해지)을 타겟으로 직접 사용**하는 방식으로 전환. Cell 단위 지표(A 순증감, KOSIS 소멸률)는 라벨이 아니라 브랜드가 속한 지역의 피처로 재활용 예정
- 모델: LightGBM 메인 트랙 계획했으나 이 환경의 애플리케이션 제어 정책이 네이티브 DLL을 차단해 scikit-learn `HistGradientBoostingRegressor`로 대체(2026-07-23). 베이스라인 Spearman 0.037 → 시계열 피처 0.084 → 표본크기 가중+정규화 0.161 → **경쟁밀도(반경 250m/500m) 피처 추가 후 최종 RMSE 0.2354(베이스라인 0.2386 이김)/Spearman 0.1653**(2026-07-23, 현재 최종 성능). 브랜드 개별 이력(시계열/등록취소이력/본부재무)은 커버리지를 100%까지 올려도 SHAP 기여도 0으로 확인돼 전부 기각 — 유효했던 신호는 업종 피어평균, 정적 비용/업종 피처, 경쟁밀도 세 축. 캘리브레이션은 보류, 여유 시 lifelines 생존분석 보조 트랙

### 2026-07-23 (계속) — 1순위 타겟 노이즈 진단 + 2순위 데이터 재처리, 개선의 실제 원인 특정
사용자 요청("지금 문제를 해결하기 위해서 필요한 자료나 과정 검토, 우선순위 나열")에 따라 5단계 우선순위를 세우고 상위 2개를 실행:

**1순위 — 타겟 노이즈 진단** (`src/models/diagnose_target_noise.py` 신설): 브랜드의 74%가 가맹점 10개 미만이라 타겟(해지율) 분산 대부분이 소표본 노이즈일 가능성을 확인. `sample_weight=sqrt(연초가맹점수)` 가중회귀 + 가맹점 10개 이상 서브셋 평가를 조합한 결과 Spearman이 0.084→0.097(가중)→0.122(서브셋)→0.158(가중+서브셋)로 일관되게 개선. 단, RMSE는 어떤 케이스에서도 평균-예측 베이스라인을 못 이겨 **노이즈가 실재하지만 단독 원인은 아님**을 확인 — 표본크기 가중을 기본값으로 채택.

**2순위 — 미활용 데이터 재처리**: (1) 1105(지역별 매출) 파싱 버그 발견·수정 — 기존 코드가 지역별 값을 전국값으로 오인해 흡수하던 구조적 오류였음, 수정해도 커버리지는 여전히 낮아(~1%) 모델에는 미포함. (2) 1111(등록취소 사유) 이력을 1년 지연시켜 피처화(커버리지 100%). (3) §8에서 커버리지 부족(15~40%)으로 SHAP 0이었던 시계열 피처 3종에 연도별 평균 imputation 적용(커버리지 99.9%로 상승).

**재검증 결과(표본크기 가중 반영)**: RMSE 0.2425(베이스라인 0.2386과 거의 근접), Spearman **0.156**. 하지만 SHAP 확인 결과 **이 개선은 전부 1순위(표본크기 가중)에서 온 것**이고, 2순위에서 추가/보강한 신규 피처(1111 취소이력 2종 + imputed 시계열 3종, 커버리지 100%/99.9%임에도) 전부 SHAP 기여도 정확히 0. §8의 "커버리지 부족 때문에 안 쓰인다"는 가설은 **반증**됨 — 브랜드 개별 이력과 이듬해 해지율 사이엔 애초에 실질적 상관관계가 없다는 뜻. 남은 유효 신호는 업종x연도 피어 평균과 브랜드 정적 속성(비용구조/업종/업력) 두 종류뿐으로 좁혀짐. 자세한 내용: `docs/design.md`의 "9. 1순위 진단 + 2순위 피처 보강"

### 2026-07-23 (계속) — 3순위: 피어평균 과의존 완화 시도 → 애초 전제가 뒤집힘
`induty_peer_avg_discontinuation_rate`가 SHAP 1위를 독점하는 현상을 정규화(`l2_regularization`/`min_samples_leaf` 그리드서치)로 완화할 수 있는지 확인(`src/models/tune_regularization.py`). **결과**: 정규화 강도를 바꿔도 이 피처의 SHAP 지배력(1위/2위 비율 약 2.8~2.9배)은 거의 그대로였고, 오히려 이 피처를 완전히 제거하는 참고 실험에서 Spearman이 0.156→0.105로 반토막남 — **"과의존은 해롭다"는 애초 전제가 틀렸음을 확인**. 이 피처는 억제 대상이 아니라 지금까지 확보한 피처 중 거의 유일하게 신뢰할 수 있는 신호로 재평가. 다만 `l2_regularization=10`은 RMSE(0.2425→0.2415)와 Spearman(0.156→0.161) 둘 다 손실 없이 개선하는 유일한 지점이라 기본값으로 채택. **결론**: 모델 구조를 만지는 접근의 개선 여지는 대부분 소진됨 — 다음은 신규 데이터 확보(브랜드↔가맹본부 매핑, 경쟁밀도) 또는 지금 수준에서 리포트/가이드 표 작성으로 전환 판단 필요. 자세한 내용: `docs/design.md`의 "10. 3순위"

### 2026-07-23 (계속) — 4순위: 브랜드↔가맹본부 매핑 시도, 매핑은 성공했으나 신호 없음
1106(재무)/1109(법위반)을 연결하려면 브랜드↔가맹본부 매핑이 필요했는데, **FTC 12개 파일 전체(88만+건)를 확인한 결과 브랜드명과 본부명이 동시에 채워진 레코드가 0건** — 정식 매핑 키 자체가 데이터에 노출돼 있지 않음을 확인. 대안으로 "본부명==브랜드명 정확 일치"(1개 브랜드=1개 회사인 소형 프랜차이즈에서 흔함) 방식으로 매핑해 연결 — 브랜드 3,443개 중 351개(재무, 10.2%)/2개(법위반, 0.06%) 매핑 성공. 영업이익/총자산/당기순이익/총부채/총매출/자본총계/부채자본비율(1106) + 시정조치수/민사소송실패수/과징금조정건수(1109) 10개 피처 추가 후 재학습. **결과**: RMSE·MAE·Spearman이 소수점까지 완전히 동일(모델이 새 피처를 전혀 안 씀), SHAP도 10개 전부 기여도 0 — 타겟 매칭 기준 실제 커버리지가 2~3%(재무)/0.08%(법위반)로 너무 낮았던 게 원인. §8/§9에서 반복된 "낮은 커버리지 → SHAP 0" 패턴이 네 번째로 재현됨. 매핑 방법(정확 일치만 지원, 다브랜드 회사 누락) 자체의 한계이지 "본부 재무건전성은 무관하다"는 증거는 아님 — 더 밀려면 매핑 정교화가 선행돼야 함. 4순위도 소진, §10의 리포트 전환 결론 유지. 자세한 내용: `docs/design.md`의 "11. 4순위"

### 2026-07-23 (계속) — 경쟁밀도 피처: 처음으로 RMSE가 베이스라인을 이김, 순위상관은 악화
1순위(경쟁밀도)를 재개. sbiz 상가업소(274만 건, 202603 단일 시점)에는 브랜드명이 없어 `상호명` 문자열에 브랜드명이 부분일치하는지 Aho-Corasick 다중패턴 매칭(`pyahocorasick` 신규 설치)으로 검색 — 타겟 브랜드 3,443개 중 **2,807개(85%)가 최소 1개 이상 매칭**(총 90,218개 점포). 매칭된 점포마다 같은 업종소분류 내 반경 250m/500m 경쟁 점포 수를 BallTree로 계산해 브랜드 단위로 평균(`src/features/sbiz_competition.py`). **커버리지 82.6%(3,263/3,951)** — 지금까지 추가한 신규 피처 중 최고. **결과**: RMSE **0.2344 — 이 프로젝트 전체에서 처음으로 평균값 예측 베이스라인(0.2386)을 이김**(1.8% 개선). 하지만 Spearman은 0.161→0.132로 오히려 나빠짐. ### 2026-07-23 (계속) — 매칭점포수 재검증 → 제거하니 세 지표 모두 최고치 갱신

### 2026-07-23 (계속) — DoD 잔여 3개 항목 완주: decile/subgroup 검증 → 캘리브레이션 → pipeline.py
사용자 요청("모델을 다 만든 거야?" → "끝까지 만들어야지 차례대로 진행해줘")에 따라 DoD에 남아있던 마지막 세 항목을 순서대로 완료.

1. **decile/subgroup 검증**(`src/models/evaluate.py`): valid를 예측 위험도 10분위로 나누자 실측 해지율이 완벽히 단조감소(1분위 0.251 → 10분위 0.091, 상하위 10% 간 2.75배 차이) — Spearman만 보면 약해 보였지만 극단 그룹 분리력은 실용적으로 쓸만함. 다만 **업종별로 쪼개보니 서비스 업종은 Spearman 0.02로 순위분별력이 거의 사라짐**(전체 평균 0.165가 이 편차를 가리고 있었음), 대형 브랜드(≥10점)는 0.227로 뚜렷이 더 좋음 — 종합 지표만 보고 "이 모델이 어디서나 똑같이 작동한다"고 오해하면 안 됨을 확인.

3. **`pipeline.py`**: 원래 스텁은 폐기된 Cell 2단계 구조(주소→좌표) 전제였던 걸 브랜드 피처 dict 입력 방식으로 전면 재작성. `python -m src.pipeline --input-json <파일>`로 raw/calibrated 스코어 출력 확인(`docs/pipeline_input_example.json`). 구현 중 범주형 컬럼 predict-time 카테고리 불일치로 인한 `TypeError`를 발견·수정(학습 데이터 전체의 카테고리 목록을 명시 지정하는 방식으로 해결).

v2의 매장별 신호(상권변화지표·추정매출·유동인구·소비지출)를 실측 생존 라벨에 추가해
교차 검증 — 브랜드 내부 AUC가 0.5063→**0.5216**으로 개선돼, 이 신호들이 CLSBIZ_RT라는
셀 집계 타겟에만 통하는 게 아니라 **진짜 매장 단위 실측 결과에도 일반화된다**는 것을
처음 확인함. 다만 전국 모델(0.5411)보다는 여전히 낮아 서울 부분집합의 표본 부족이
