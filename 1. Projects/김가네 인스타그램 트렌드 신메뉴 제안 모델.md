## 핵심 설계 요약
- **파이프라인**: Instagram 게시물 수집(Agent-Reach/OpenCLI) → 캡션/좋아요 텍스트화 → 프랜차이즈 메뉴 CSV와 함께 LLM 프롬프트 구성 → Claude API 호출 → 신메뉴 제안 텍스트 출력
- **Instagram 접근 방식**: Agent-Reach의 Instagram 채널은 공식 API가 아니라 **OpenCLI(브라우저 확장)가 사용자의 Chrome instagram.com 로그인 세션을 재사용**하는 방식. 계정 소유자 본인의 실제 로그인이 필요하고, 호출 빈도가 높으면 "로그인 필요" 형태의 사실상 레이트리밋이 발생함(문서에 정확한 리셋 주기 명시 없음)
- **비용 구조**: Agent-Reach 자체는 무료/오픈소스. 신메뉴 제안 생성 단계(`suggest`)만 Anthropic API를 호출하므로 Claude Pro 구독과 무관하게 별도 종량 과금(호출당 1센트 미만 수준). 사용자가 API 키 발급 전이라, 1차 검증은 API 호출 없이 이 대화에서 직접 프롬프트 결과를 생성하는 방식으로 대체함
- **레이트리밋 대응 전략**: 계정 차단 리스크를 줄이기 위해 짧은 재시도 대신 **키워드(브랜드)당 30분 간격, 총 9개 브랜드(엽기떡볶이/신전떡볶이/죠스떡볶이/국대떡볶이/청년다방/배떡/두바이초콜릿/탕후루/마라탕후루)를 약 3시간에 걸쳐 순차 수집**하는 백그라운드 스크립트로 전환

## 리스크 & 대응
- **계정 차단 리스크**: Instagram이 공식 API가 아니라 브라우저 세션 재사용 방식이라, 과도한 호출 시 사용자 본인 계정에 제약이 걸릴 수 있음 → 30분 간격 저속 수집으로 완화, 실패 시 즉시 재시도하지 않고 다음 사이클까지 대기
- **레이트리밋 리셋 주기 불명확**: Agent-Reach 공식 문서에 정확한 429/로그인요구 해제 시간이 명시돼 있지 않음 → 보수적으로 긴 간격(30분) 채택, 필요시 간격 추가 조정
- **큰 계정(예: BuzzFeed Tasty) 접근 실패**: 첫 성공 이후 곧바로 이후 호출이 모두 "로그인 필요" 에러로 실패 → 계정 크기 문제가 아니라 순수 호출 빈도 문제로 판단(작은 계정 첫 호출은 성공했었음)
- **API 비용 부담**: 사용자가 Anthropic API 키 미보유 상태 → 발급 전까지는 대화창에서 직접 프롬프트 결과를 생성하는 방식으로 우회, 필요 시 나중에 API 키 발급해 자동화

### 2026-08-07 — 할당량 구조 파악 + `--top` 기본값 10→50 상향(할당량 추가 소모 없음)
